# 벤치마크 (PoC, 2026-10-09)

**측정 환경:** LG gram 16ZD90Q, i5-1240P, RAM 16GB, RTX 2050 4GB(드라이버 610.47), Windows 11,
Python 3.11.13, faster-whisper 1.2.1 / CTranslate2 4.8.2, sherpa-onnx 1.13.8, onnxruntime 1.31.

**테스트 데이터:** `tests/fixtures` 아래 TTS 음성 3개(Microsoft Heami, 문장 21개, 81초).
회의에서 자주 나오는 영단어(QA, deadline, API, PR 등)가 들어 있습니다.
TTS 음성은 실제 Zoom 음성보다 깨끗하므로, **이 숫자는 회귀 확인용 기준선**으로 봐야 합니다.
실제 회의 정확도는 녹음 샘플로 따로 측정해야 합니다.

재현:
```powershell
uv run python scripts/make_fixtures.py
uv run scribe bench whisper
uv run scribe bench sherpa --partial-model kspon174m-c16
uv run scribe bench e2e
```

## 확정 자막: faster-whisper large-v3-turbo int8_float16 (GPU)

| 설정 | RTF | 문장당 처리 p50 / p95 | 최대 VRAM 증가 | CER |
|---|---|---|---|---|
| beam 1, 타임스탬프 없음 | 0.188 | 0.67s / 0.92s | 1297 MiB | 6.1% |
| beam 3, 타임스탬프 없음 | 0.240 | 0.93s / 1.00s | 1297 MiB | 5.2% |
| **beam 3, 타임스탬프 (기본값)** | **0.194** | **0.75s / 0.85s** | **1297 MiB** | **5.6%** |

타임스탬프 모드를 기본값으로 정한 이유: 문장 두 개가 한 구간에 들어 있을 때, 타임스탬프 없이 돌리면
첫 문장만 출력하고 나머지를 버리는 사례가 실제 루프백 테스트에서 나왔습니다.
타임스탬프 모드에서는 두 문장이 모두 나왔습니다.

## 임시 자막: sherpa-onnx 스트리밍 (CPU, 스레드 2개)

첫 글자 지연은 발화 시작부터 첫 텍스트가 나올 때까지의 시간입니다. 파이프라인과 같은 조건이 되도록 200ms 프리롤을 넣었습니다.

| 모델 | RTF | 첫 글자 p50 / p95 | CER |
|---|---|---|---|
| zipformer-ko (공식 2024-06-16) | 0.153 | 0.90s / 1.91s | 24.8% |
| **kspon174m-c16 (기본값)** | **0.197** | **1.01s / 1.02s** | **9.9%** |
| kspon174m-c32 | 0.123 | 1.33s / 1.34s | 17.3% |

스레드 수 비교(kspon174m-c16): 1개는 RTF 0.269, 2개는 **0.197**, 4개는 0.368입니다.

첫 글자 지연이 약 1초인 것은 **모델 자체의 특성**입니다. 이 모델은 320ms 단위로 디코딩하는데,
"서버"처럼 0.5초 안에 끝나는 단어도 0.95초 시점에야 처음 출력합니다.
파이프라인이 더하는 지연은 거의 없습니다.

## 확정 자막 모델 비교: large-v3-turbo vs large-v3 (2026-10-10)

GUI 왼쪽 아래 **확정 자막 모델**(또는 `scribe run --final-model`)에서 고를 수 있습니다. 기본값은 turbo입니다.

| 항목 | large-v3-turbo (기본) | large-v3 |
|---|---|---|
| 실제 발화 2분, RTF (beam 3) | 0.10 | 0.25 |
| 15초 발화 확정 시간 | ~1.1s | ~2.3–2.8s |
| VRAM 증가 (단일 구간 / 연속 10구간 최대) | +1.3 GB | +2.2 GB / +3.2 GB |
| 모델 로드 (디스크 캐시 상태) | ~5s | ~10s (전환 시 15–33s) |
| TTS 테스트셋 CER | 5.6% | 5.8% |

실제 대화체에서는 large-v3가 일부 오인식을 바로잡았지만(“꼴리기→꼴 보기”, “에이석→에이서”,
“느끼지가→믿기지가”) 새 오류도 만들었습니다(“공대생→공개생”, 짧은 발화 일부 생략).
RTX 2050(4GB)에서는 Zoom·브라우저 등 다른 프로그램이 GPU를 쓰면 메모리가 부족해질 수 있어
(측정 시 다른 앱 포함 3.7/4.0 GB) 기본값은 turbo로 둡니다.

## 상대 화자 구분 (2026-10-10)

확정 문장마다 3D-Speaker CAM++ 음성 임베딩(CPU, 음성 1초당 약 14ms → 문장당 +0.1~0.2초)을 뽑아
지금까지의 화자 평균과 비교합니다(유사도 ≥ 0.6이면 같은 사람, 2초 미만 발화는 새 화자를 만들지 않음, 최대 10명).

실제 녹음(영상 2개, 2분 20초)에서 문장 단위 유사도: 같은 진행자 0.96, 같은 대화 화자 0.76–0.90,
다른 사람 0.13–0.32 → 라벨 `AABBBBBBCB`(첫 영상 진행자 A, 카페 대화 B). 1.5초 창 단위 판단은 2~3명을 13~39명으로
쪼개 실시간 구분에 쓰지 않았고, 영어(VoxCeleb) 모델은 모두를 한 명으로 묶어 제외했습니다.
정답 라벨이 있는 실제 Zoom 회의로는 아직 검증하지 않았습니다.
